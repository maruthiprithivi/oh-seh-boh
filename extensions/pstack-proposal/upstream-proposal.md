PStack's local orchestration ledger records verification and queues; it does not establish shared ownership between independent coordinators on different hosts. This proposal adds a separate opt-in `osb-coordination` skill and small standard-library client for an operator-provisioned compatible authority. Existing `orch`, TSV/JSON formats, named stacker, manifests and default behavior stay unchanged. OSB remains independently maintained at https://github.com/maruthiprithivi/oh-seh-boh.

The versioned client boundary (`pstack.osb.client.v1`) currently maps a discovered schema-10 `firstmate.scoped.v2` endpoint using existing `coord.project.v1` wire semantics. No implementation is bundled, fetched or installed and ordinary PStack does not require it. Another authority needs a reviewed adapter mapping. The client binds fixed route/scope/repository/home identity, persists request bytes before dispatch, reuses stable keys after lost replies, reauthorizes replay remotely and checks current claim plus declared revision at a cooperative checkpoint. It executes no Git/CI/merge/deploy effect and offers no atomic fence around subsequent external commands. Generic completion and named task-writer handoff are not invented.

Source fixtures target an explicitly supplied, pinned, clean authority in a disposable Linux DB: two independent coordinators and barrier contention, lost reply/retry, stale ownership, wrong-holder release, successor progress, declared revision binding and unavailable authority. External effects are local mocks. This is a **source-only, unvalidated draft**: no builds, imports, tests, lint, hooks or installs have run. Approved remote validation is blocked by authentication/credits/capacity; affected-check estimate 5–10 minutes on that same allocation. Missing fixtures/source cannot count as passing. Real SSH/harness compatibility, live forge revision/admission and migration/recovery remain separate acceptance.

Retains PStack's MIT notices/terms; does not select a license for OSB. Seeking review of this narrow optional boundary, not maintainer acceptance, merge or deployment. No live credentials, permissions, infrastructure or user-harness configuration are changed.
