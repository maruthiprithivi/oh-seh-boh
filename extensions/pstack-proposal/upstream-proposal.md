PStack's local orchestration ledger records verification and queues; it does not establish shared ownership between independent coordinators on different hosts. This proposal adds a separate opt-in `osb-coordination` skill and small standard-library client for an operator-provisioned compatible authority. Existing `orch`, TSV/JSON formats, named stacker, manifests and default behavior stay unchanged. OSB remains independently maintained at https://github.com/maruthiprithivi/oh-seh-boh.

The versioned client boundary (`pstack.osb.client.v1`) currently maps a discovered schema-10 `firstmate.scoped.v2` endpoint using existing `coord.project.v1` wire semantics. No implementation is bundled, fetched or installed and ordinary PStack does not require it. Another authority needs a reviewed adapter mapping. The client binds fixed route/scope/repository/home identity, persists request bytes before dispatch, reuses stable keys after lost replies, reauthorizes replay remotely and checks current claim plus declared revision at a cooperative checkpoint. It executes no Git/CI/merge/deploy effect and offers no atomic fence around subsequent external commands. Generic completion and named task-writer handoff are not invented.

Source fixtures target an explicitly supplied, pinned, clean authority in a disposable Linux DB: two independent coordinators and barrier contention, lost reply/retry, stale ownership, wrong-holder release, successor progress, declared revision binding and unavailable authority. External effects are local mocks. This is a **source-only, unvalidated draft**: no builds, imports, tests, lint, hooks or installs have run. Approved remote validation awaits capacity sharing approval and credit verification. Missing fixtures/source cannot count as passing. Real SSH/harness compatibility, live forge revision/admission and migration/recovery remain separate acceptance.

The explicitly enabled local verifier runner wires one protected path: deterministic scoped submit/claim before a fixed trusted foreground command, lease renewal during work, clean local base/head/branch/origin checks and a live checkpoint before the existing `orch ledger record`, then owned-process quiescence before fenced release. Durable phases prevent blind relaunch after an uncertain worker or verdict effect. The operator fixes the command and its success verdict and supplies preinstalled PStack/Bun plus an initialized local store. Ten real-authority/mock-publisher lifecycle fixtures cover this wiring; they are unexecuted and do not certify the installed PStack store. This is not native Cursor Task interception, process sandboxing or an atomic fence around the local record/forge actions. Installed-PStack acceptance remains separately required. Estimated client plus mock lifecycle checks: 7–15 minutes, and installed path 5–10 more, excluding provisioning. Authentication is restored; shared-capacity approval and credit verification remain pending, with no new spend authorized.

Preflight rejects unavailable fixed executables and missing stores, validates the verification ledger through the native read before acquisition, and places the first claim/bound persistence under signal handling and exact-claim cleanup. Unknown claim responses retain the acquiring phase without a guessed release. Regression coverage includes invalid-store repair with the same attempt and bound-transition signal/write-failure cleanup.

Retains PStack's MIT notices/terms; does not select a license for OSB. Seeking review of this narrow optional boundary, not maintainer acceptance, merge or deployment. No live credentials, permissions, infrastructure or user-harness configuration are changed.
