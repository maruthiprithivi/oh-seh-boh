# Reference lab versus a real authority

The public OSB lab uses `osb.lab.v1`, with synthetic identities and test-only setup/recovery commands. It is deliberately separate from any operational authority. Passing it checks the reference transition model; it cannot certify another implementation, an authenticated SSH deployment, a GitHub CAS client or installed harness compatibility.

For an existing authority, pin its owner's released/provisional contract and source version in an approved private capability mapping. Read the owner's documented operation/schema fields and limits. Map scope identity, authenticated principal, authority/recovery identity, membership/session/claim/primary/slot fences, lease clock, request replay, revocation and error receipts explicitly. A JSON shape that looks similar is not compatibility.

`lab/client.py:invoke_existing_endpoint(client_handle, operation, payload)` provides a small process-framing layer for `coord.project.v1`. The supervisor supplies fixed argv selecting endpoint code, database and **fixed synthetic principal** in an isolated integration fixture, or a separately approved fixed authenticated route. Task JSON never chooses the principal/database. Its envelope has exactly `protocol`, `operation`, `payload`; it rejects oversized requests/body identity fields, requires current authority identity where documented, and checks both process exit and receipt `ok`. This layer is source-only and unexecuted; it is not a complete lifecycle adapter or deployment installer.

Wire names do not certify capabilities. The smoke now requires explicit `--capability-mapping legacy-experimental` or `--capability-mapping osb-firstmate.coord.project.v2` in addition to the exact clean source pin. V2 requires authenticated discovery with wire `coord.project.v1`, integer schema 10 and profile `firstmate.scoped.v2`; legacy experimental discovery must lack those v2 fields. A mismatch stops invitation/join and writer calls and fails the report. Local initialization and synthetic scope setup precede discovery in this disposable fixture; this is not a live setup tool. The old experimental scoped-five lineage cannot be overlaid onto v2's preserved migrations 001–009 plus 010. Supplied source and private capability mapping remain supervisor-approved inputs, not guessed installed versions. The framing layer's historical `granted` boolean is only process success plus `ok:true`; a v2 CI receipt with `admitted:false` is queued and cannot authorize CI.

`lab/integration_smoke.py` uses that framing layer against an explicitly supplied, pinned clean owner source checkout in a fresh disposable database, with fixed synthetic Alice/Bob handles. The default `--profile membership` checks initialization, current authority discovery/capability, targeted invitation/join replay and stale-authority refusal. It imports no owner implementation code and downloads nothing; this optional test requires separately available approved source. Example authorized invocation: `python3 lab/integration_smoke.py --test-only --capability-mapping osb-firstmate.coord.project.v2 --source /approved/owner-source --expected-source-commit VERIFIED_COMMIT --output evidence/owner-smoke.json`. The standalone OSB lab and cooperative skill do not require this source.

Optional `--profile writer` adds enrollment and fresh sessions, intents with a fixed synthetic base OID, one granted claim and a second writer's overlapping-file refusal, exact grant and denial replay, live claim check, lease renewal, release, a new successor claim with increasing fence, and refusal of a revoked writer's check and cached-grant replay. V2 also requires the `head_oid:null` field before any head publication. The two claims are sequential; this is not a simultaneous race test or named handoff. Each writer uses a separate branch so the conflict assertion specifically exercises the shared file. It writes no repository, merge, deployment or real GitHub effect. Missing required checks or unexpected receipt shapes produce failed/incomplete evidence. Negative checks require the documented exact refusal diagnostic and exit status; unrelated process failures cannot count as enforcement. These source-specific assertions must be reviewed when the pinned contract changes. Example: `python3 lab/integration_smoke.py --test-only --profile writer --capability-mapping osb-firstmate.coord.project.v2 --source /approved/owner-source --expected-source-commit VERIFIED_COMMIT --output evidence/owner-writer-smoke.json`. Passing this bounded source smoke is still not concurrency/load/recovery acceptance, a complete lifecycle adapter or deployed transport proof. Both profiles are currently unexecuted.

V2's wrapper PID/start/host/attempt identity, primary-owned wrapper session, scoped CI capacity/admission and safe unmerged settlement require separate owner suites. This smoke invokes none of them. Inherited settlement can release proved unmerged outcomes under its wrapper/quiet-period/live-forge conditions; ambiguous outcomes remain occupied. Local dispatch takes `TASK PROJECT WORKTREE BRIEF BRANCH HARNESS`, but this fixture does not exercise adapter dispatch. Generic complete, atomic named task-writer transfer and GitHub projection remain absent. No capability discovery result is a live merge/deploy authorization.

Required integration acceptance after allocation: use the actual owner's public-interface suites for competing claims, targeted joins/roles, cross-scope refusal, receipt replay after lost response, current authority identity, restore before scope/member/home creation, permanent recovered bindings, revocation before replay, primary-epoch fencing, occupied integration slots, immutable repository/origin/PR checks, partition refusal and per-principal outbox acknowledgment. Do not replace those tests with canned fixture responses from the OSB model.

If using `coord.project.v1`, discover current non-secret authority identity via authenticated `authority-info`; scoped requests except `scope-status` carry it, including targeted join. Verify GitHub.com immutable scope mapping and actual origin/repository identity at guarded checkpoints. Preserve old authority IDs in delayed requests so recovery rejects them; do not rewrite stale requests to current identity. The source-specific mapping wins over generic OSB lifecycle vocabulary.

Known capability boundaries must stay visible: integration-primary transfer is not task-writer transfer; generic completion, atomic named task-writer handoff and GitHub projection may be absent. Release/new claim has an unowned interval and guarantees no named successor. Ambiguous unmerged external attempts can remain occupied pending reviewed recovery. Ledger fences do not control arbitrary direct forge actions. Synthetic fixed-principal invocation is not proof that live SSH keys/accounts bind identity or prevent database access.

Real harness acceptance is a separate manual matrix: installed product/version; skill discovery/path; loaded references; verified actor/scope; join/resume; refused stale claim; evidence/handoff behavior; gate invocation before shared effects. No real provider prompts, harness installation or spend is implied by this repository. Use approved credentials and disposable scope; no volume stress against live GitHub or other users. A bounded live smoke test needs its exact scope and actions approved first.
