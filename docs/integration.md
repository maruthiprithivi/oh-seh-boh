# Reference lab versus a real authority

The public OSB lab uses `osb.lab.v1`, with synthetic identities and test-only setup/recovery commands. It is deliberately separate from any operational authority. Passing it checks the reference transition model; it cannot certify another implementation, an authenticated SSH deployment, a GitHub CAS client or installed harness compatibility.

For an existing authority, pin its owner's released/provisional contract and source version in an approved private capability mapping. Read the owner's documented operation/schema fields and limits. Map scope identity, authenticated principal, authority/recovery identity, membership/session/claim/primary/slot fences, lease clock, request replay, revocation and error receipts explicitly. A JSON shape that looks similar is not compatibility.

`lab/client.py:invoke_existing_endpoint(client_handle, operation, payload)` provides a small process-framing layer for `coord.project.v1`. The supervisor supplies fixed argv selecting endpoint code, database and **fixed synthetic principal** in an isolated integration fixture, or a separately approved fixed authenticated route. Task JSON never chooses the principal/database. Its envelope has exactly `protocol`, `operation`, `payload`; it rejects oversized requests/body identity fields, requires current authority identity where documented, and checks both process exit and receipt `ok`. This layer is source-only and unexecuted; it is not a complete lifecycle adapter or deployment installer.

`lab/integration_smoke.py` uses that framing layer against an explicitly supplied, pinned owner source checkout in a fresh disposable database, with fixed synthetic Alice/Bob handles. It checks initialization, current authority discovery, targeted invitation/join replay and stale-authority refusal. It imports no owner implementation code and downloads nothing; this optional test requires separately available approved source. Example authorized invocation: `python3 lab/integration_smoke.py --test-only --source /approved/owner-source --expected-source-commit VERIFIED_COMMIT --output evidence/owner-smoke.json`. Passing membership/framing smoke is still not claim/load/recovery acceptance or deployed transport proof. The standalone OSB lab and cooperative skill do not require this source.

Required integration acceptance after allocation: use the actual owner's public-interface suites for competing claims, targeted joins/roles, cross-scope refusal, receipt replay after lost response, current authority identity, restore before scope/member/home creation, permanent recovered bindings, revocation before replay, primary-epoch fencing, occupied integration slots, immutable repository/origin/PR checks, partition refusal and per-principal outbox acknowledgment. Do not replace those tests with canned fixture responses from the OSB model.

If using `coord.project.v1`, discover current non-secret authority identity via authenticated `authority-info`; scoped requests except `scope-status` carry it, including targeted join. Verify GitHub.com immutable scope mapping and actual origin/repository identity at guarded checkpoints. Preserve old authority IDs in delayed requests so recovery rejects them; do not rewrite stale requests to current identity. The source-specific mapping wins over generic OSB lifecycle vocabulary.

Known capability boundaries must stay visible: integration-primary transfer is not task-writer transfer; generic completion, atomic named task-writer handoff and GitHub projection may be absent. Release/new claim has an unowned interval and guarantees no named successor. Ambiguous unmerged external attempts can remain occupied pending reviewed recovery. Ledger fences do not control arbitrary direct forge actions. Synthetic fixed-principal invocation is not proof that live SSH keys/accounts bind identity or prevent database access.

Real harness acceptance is a separate manual matrix: installed product/version; skill discovery/path; loaded references; verified actor/scope; join/resume; refused stale claim; evidence/handoff behavior; gate invocation before shared effects. No real provider prompts, harness installation or spend is implied by this repository. Use approved credentials and disposable scope; no volume stress against live GitHub or other users. A bounded live smoke test needs its exact scope and actions approved first.
