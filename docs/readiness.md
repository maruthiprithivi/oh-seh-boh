## Reproducible Linux job

Use [validation/run.py](../validation/run.py) and [plan.example.json](../validation/plan.example.json) only after the supervisor admits an existing Linux route. The job runs serially and requires explicit 1–2 CPU affinity IDs already imposed by that supervisor; it never chooses CPUs, creates a cgroup/VM, connects an account or grants SSH access. Source checkouts, preprovisioned dependencies, reviewed owner validator and private output directory must already exist. The example defaults to unauthorized and contains deliberately unresolved owner pins/hashes. A true config flag does not substitute for user/supervisor authorization.

The job's source folder is separate from its pinned OSB target: the example tests published `61744a0`, whose lab is unchanged. Extract or check out the reviewed validation packet separately, verify its immutable archive/commit, and fill the private plan with the supplied authority pin and owner-validator SHA256. Do not bundle private source/pins or live credentials into the public example. The script accepts an existing validator with the documented `bash JOB SOURCE EVIDENCE` interface, verifies its hash, and records its exit/logs. It does not claim a validator with arbitrary contents covers the required owner suites; the supervisor must review its suite inventory.

The consolidated job also requires an existing exclusive cgroup-v2 containment controlled by the supervisor, initially containing only the job. New verifier/publisher process sessions still inherit that containment. The job creates no cgroup, changes no membership and never places shared workloads there; missing containment/pidfd support refuses setup. Stage completion requires both its process group and the entire admitted descendant containment to quiesce. Cleanup signals only bound pidfds whose membership is still verified. If a process escaped that boundary, stop for supervisor reconciliation rather than guessing a PID. Initial/final pin checks use the shared remaining deadline. The parent supplies the external wall/spend watchdog and emergency settlement for job death or unresponsive storage/kernel operations; a config flag cannot prove such supervision exists.

## Measurable acceptance

Safety gates are zero overlapping live grants, lost acknowledged transitions, stale/unauthorized writes, unacknowledged/duplicate sink effects, unresolved live claims after profile cleanup, missing workers and missing/corrupt evidence. Known-positive controls must pass and specific mutant counterexamples must be detected. Actual PStack must record exactly the expected PR/head/verdict with evidence on success and no verdict on cancellation/revocation; invalid setup must start no worker. These gates cannot be waived for a pilot.

The example's provisional capacity targets are >=1 measured operation/second, p99 <=2 seconds and Jain fairness >=0.5 for independent/contention profiles at eight synthetic agents. These are predeclared acceptance targets, **not measured capability or production SLOs**. Record actual operations, wall duration, profile bounds, per-actor successes, retry distribution, CPU/RSS and storage. The `seconds` argument is a ceiling; finite attempts can finish early. A profile named soak therefore does not prove a sustained run. Longer-duration real-authority workload, crash/restart, backup/restore and availability evidence need separately authorized tests and workload-specific targets. Aggregate RSS/cost are supervisor measurements; max child RSS alone is not total fleet usage.

## Controlled pilot versus production

Consider a controlled pilot only after exact-source owner suites, all 15 fixtures, actual PStack cases, mutation controls and bounded profile gates pass with retained evidence and reviewed limitations. Restrict it to one approved repo, two trusted homes, fixed read-only local verifiers and the existing local verdict record. Retain a named human primary/integration owner, one PStack-store writer, human integration review and ordinary repository protection. Operators must rehearse cancellation, lost acknowledgment, unavailable route and unknown verdict reconciliation, and accept cooperative TOCTOU/process-group limits explicitly. This source packet does not activate the pilot.

Production requires additional measured sustained workload and recovery/restore evidence on the actual released authority, transport security/principal mapping and revocation validation, backup/RPO/RTO drills, monitoring/on-call/retention and rollback rehearsal, installed harness acceptance, approved dependency/version policy and license decision for OSB. A requirement to prevent stale external Git/CI/merge writes additionally blocks production until protected consumers atomically validate the fence or all writes traverse an approved gateway. Do not label cooperative credentials as enforced fencing.

Remaining source gaps are deliberately bounded: no generic osb/1 adapter executable or CAS client, no GitHub projection for the actual authority, no automatic heartbeat daemon/Task dispatch, no enforceable external gateway and no general task completion/atomic writer handoff mapping. They are not prerequisites for the restricted local-verifier pilot, but any workflow needing them must stop or use a separately reviewed capability. Do not add them before obtaining the first actual test evidence.
